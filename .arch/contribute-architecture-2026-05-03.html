Architectural invariants

  • Gates are deterministic and read-only. No gate writes state; failures BLOCK transitions.
  • Dossier is the single source of truth for repo rules. Researcher writes; gates read.
  • Markdown is the cache. Every byte is grep-able; no DB. Phase 3 MCP is index, not replacement.
  • Active and state planes are separate. Active layer can be rebuilt from scratch; state is canonical.
  • Lazy clone, lazy fork. External effects only at user-initiated transitions.

OSSBot (/contribute) — Slice 2 Architecture

Three-layer safety system: orchestrator walks the candidate lifecycle, subagents handle discovery + research, and 62 deterministic gates verify every external action against repo-specific rules captured in per-repo dossiers. Designed to make AI-assisted OSS contribution mechanically reliable — and to make "AI slop" structurally impossible to ship.

Component details

Orchestrator: /contribute SKILL.md

  • Walks the candidate lifecycle: open → shortlist → claimed → working → submitted → merged (or dropped).
  • Every state transition calls transition.sh with the candidate + intended action; runner aggregates gate verdicts; BLOCK halts the transition.
  • Auto-invokes @researcher refresh when the dossier for the touched repo is missing or older than 14 days.
  • Hard-stop on AI policy strikes (gate E2): mandatory --override-gate=E2 "<reason>" for the second submission to a repo that previously closed under AI policy.

Subagents: @scout and @researcher

  • User-scope subagents (~/.claude/agents/); invokable as @scout / @researcher from any session.
  • Own context windows so verbose gh output never bloats the orchestrator session.
  • Persistent memory at ~/.claude/agent-memory/<name>/MEMORY.md captures cross-repo patterns; per-repo specifics live in dossiers.
  • Both are thin LLM orchestrators on top of bundled scripts (heavy lifting in deterministic bash/Python).

62 gates · the safety net

  • One script per gate at ~/.contribute-system/gates/. Plug-in: drop a script, gate-runner discovers it via glob.
  • Severity: BLOCK halts the transition; WARN surfaces in briefing; INFORM logs only.
  • Catches the trap categories we already hit in the wild: A1 assignee check (Tracer-Cloud opensre #1129), A2 already-shipped check (PostHog #55412), plus 60 more.
  • Override mechanism: --override-gate=<id> "<reason>". Logged to log.jsonl with timestamp + user; reviewer audit trail.

State layer · markdown + JSONL

  • research/<owner>__<repo>.md — per-repo dossier; ~30 frontmatter fields (CLA, DCO, branch convention, review bots, pet peeves) plus a manually curated failure log that grows from past closures.
  • candidates/<owner>__<repo>__issue<N>.md — tracker; one file per issue. Frontmatter survives refresh; user-edited ## Notes section preserved.
  • memory bank — profile (langs/tiers), briefing (regenerated), portfolio (merged PR ladder by tier), log.jsonl (append-only audit).
  • check-runs/ — test evidence per (repo, branch); gate B14 refuses PR submission if no fresh green run exists.

External surface · gh CLI only

  • Single external dependency. No webhooks, no daemons, no MCP server in Phase 1 — the dev box has 24 prod containers + active OOM cascades; we add nothing new.
  • Read-mostly: gh issue list, gh search prs, gh api repos/X. Writes only at user-initiated transitions (gh issue comment, gh pr create --draft --fork).
  • Phase 2 (≥30 days post-Phase-1, if validated): repackage as a Claude Code plugin distributable via tonsofskills marketplace.
  • Phase 3 (only on multi-user demand): containerized MCP service on the new VPS — dossier cache + scheduled scout + GitHub webhook receiver. Personal skill stays working without it.

The "first time = full audit, every time after = flush context" guarantee

  • First time we touch a repo, @researcher runs researcher-build.sh: pulls CONTRIBUTING.md + depth-1 link follows + policy file inventory + bot detection + merge metrics.
  • Result is the dossier. Every subsequent session reads it directly — no re-scrambling.
  • 14-day staleness threshold; SKILL.md refreshes automatically when expired.
  • Each candidate's research_path: points to the dossier — context loads structurally, not by re-asking the LLM what the rules are.
